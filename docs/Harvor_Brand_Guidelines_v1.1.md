# Harvor Brand Guidelines v1.1

## Brand Mission

Harvor exists to eliminate the repetitive infrastructure every B2B
application eventually has to build.

We provide self-hosted, production-ready building blocks so developers
can focus on the software that differentiates their business.

**Brand Promise:** *Infrastructure you can trust.*

------------------------------------------------------------------------

# Brand Personality

## We are

-   Calm
-   Reliable
-   Predictable
-   Professional
-   Transparent
-   Developer-first
-   Thoughtful
-   Minimal
-   Well engineered
-   Technical
-   Intentional
-   Quietly sophisticated

## We are not

-   Flashy
-   Buzzword heavy
-   Hype driven
-   Loud
-   Trend driven
-   Consumer-app inspired

------------------------------------------------------------------------

# Visual Philosophy

Harvor interfaces should resemble professional engineering tools---not
consumer applications.

The visual language emphasizes:

-   Deep contrast
-   Strong typography
-   Intentional whitespace
-   Technical authenticity
-   Precision over decoration

Every interface should feel like software you would trust to run
production infrastructure.

------------------------------------------------------------------------

# Core Values

-   **Reliability** --- Software should be dependable and predictable.
-   **Simplicity** --- Strong defaults. Minimal configuration.
-   **Trust** --- Honest tradeoffs. No exaggeration.
-   **Clarity** --- Prefer explicit over clever.
-   **Craftsmanship** --- Every interaction should feel intentional.

------------------------------------------------------------------------

# Voice & Tone

Write like an experienced engineer helping another experienced engineer.

Prefer:

-   Short sentences
-   Active voice
-   Concrete examples
-   Honest comparisons

Avoid marketing clichés and unnecessary superlatives.

------------------------------------------------------------------------

# Logo

The lighthouse represents:

-   Guidance
-   Confidence
-   Reliability
-   Calm
-   Safe passage

Documentation and product interfaces should use the simplified
lighthouse without beams.

------------------------------------------------------------------------

# Color Philosophy

Blue is earned.

Blue exists to communicate:

-   Primary actions
-   Active navigation
-   Important values
-   Links
-   Product emphasis

Most interfaces should remain navy, slate, white, and neutral grays.

------------------------------------------------------------------------

# Authentic Technical Content

Marketing should demonstrate real engineering.

Prefer:

-   YAML
-   Docker
-   Kubernetes
-   CLI output
-   OpenAPI
-   REST examples
-   Architecture diagrams

Avoid decorative mockups that do not reflect the product.

------------------------------------------------------------------------

# Brand Test

Before shipping ask:

-   Does this feel trustworthy?
-   Does it reduce complexity?
-   Does it feel calm?
-   Would an experienced engineer trust this in production?

> **Boring in operation. Exceptional in execution.**
