# Harvor SEO Standards v1.0

## Purpose

Harvor's SEO strategy exists to help developers discover trustworthy,
production-ready infrastructure components through useful technical
content---not marketing hype.

**Primary goals**

-   Rank for technical searches with high purchase intent.
-   Build long-term authority through documentation and educational
    content.
-   Convert qualified visitors into early access requests and customers.

------------------------------------------------------------------------

# SEO Principles

-   Write for humans first.
-   Optimize for search engines second.
-   Every page should answer a real technical question.
-   Prefer depth over volume.
-   Demonstrate expertise with practical examples.

------------------------------------------------------------------------

# Target Audience

-   Software Engineers
-   Platform Engineers
-   DevOps Engineers
-   Engineering Managers
-   CTOs
-   Startup founders building B2B SaaS

------------------------------------------------------------------------

# Content Pillars

## Product Pages

Each product page should include:

1.  Problem statement
2.  Why it exists
3.  Features
4.  Installation
5.  Self-hosting
6.  Examples
7.  Screenshots
8.  FAQ

------------------------------------------------------------------------

## Documentation

Every documentation page should answer:

-   What does this solve?
-   How do I install it?
-   How do I configure it?
-   How do I operate it?
-   How do I troubleshoot it?

Documentation should be indexable.

# URL Standards

Good:

/products/authorization

/docs/authorization/getting-started

/blog/self-hosting-authentication

Avoid:

/page1

/blog/post-17

/docs?id=12

URLs should be lowercase, descriptive, and stable.

------------------------------------------------------------------------

# Titles

Target: 50--60 characters.

Format:

Page Title \| Harvor

Examples:

Authorization Service \| Harvor

Self-hosted Audit Logs \| Harvor

Avoid keyword stuffing.

------------------------------------------------------------------------

# Meta Descriptions

Target: 140--160 characters.

Requirements:

-   Explain the benefit.
-   Mention Harvor naturally.
-   Encourage clicking without exaggeration.

------------------------------------------------------------------------

# Heading Structure

One H1 only.

Then:

H2

H3

H4

Never skip heading levels unnecessarily.

------------------------------------------------------------------------

# Keywords

Prioritize intent over volume.

Examples:

-   self-hosted authentication
-   authorization service
-   audit logging
-   webhook service
-   notification service
-   production-ready infrastructure
-   OpenTelemetry
-   Docker
-   Kubernetes

Use keywords naturally.

------------------------------------------------------------------------

# Internal Linking

Every page should link to:

-   Related products
-   Relevant documentation
-   Installation guide
-   GitHub repository
-   Blog posts where appropriate

------------------------------------------------------------------------

# Images

Requirements:

-   Descriptive filenames
-   Meaningful alt text
-   SVG where practical
-   Optimized size
-   Lazy load non-critical images

------------------------------------------------------------------------

# Structured Data

Use Schema.org where appropriate.

Recommended:

-   Organization
-   SoftwareApplication
-   Product
-   Article
-   BreadcrumbList
-   FAQPage

------------------------------------------------------------------------

# Performance

Target:

-   Lighthouse Performance: 95+
-   Accessibility: 100

-   SEO: 100

-   Fonts
-   Images
-   JavaScript

------------------------------------------------------------------------

# Accessibility

SEO depends on accessibility.

Requirements:

-   Semantic HTML
-   Keyboard support
-   Proper heading hierarchy
-   Descriptive links
-   Alt text
-   Sufficient contrast

------------------------------------------------------------------------

# Technical SEO

Include:

-   sitemap.xml
-   robots.txt
-   canonical URLs
-   Open Graph tags
-   Twitter/X Card tags
-   favicon
-   manifest.webmanifest

Prevent duplicate content.

------------------------------------------------------------------------

# Social Sharing

Every page should define:

-   og:title
-   og:description
-   og:image
-   og:url

Use a consistent Harvor social preview image.

------------------------------------------------------------------------

# Documentation SEO

Documentation is a product.

Each page should include:

-   Search-friendly title
-   Code examples
-   Copy buttons
-   Troubleshooting
-   Related pages
-   Last updated date

------------------------------------------------------------------------

# Writing Standards

Use:

-   Active voice
-   Short paragraphs
-   Clear examples
-   Honest language

Avoid:

-   "Revolutionary"
-   "Game-changing"
-   "AI-powered" unless objectively relevant
-   "Best-in-class"

Write like an experienced engineer helping another engineer.

------------------------------------------------------------------------

# Analytics

Track:

-   Organic traffic
-   Landing pages
-   CTA click-through rate
-   Early access conversions
-   Documentation engagement
-   Referral sources

Success is measured by qualified developer engagement, not page views
alone.

------------------------------------------------------------------------

# Final SEO Test

Before publishing ask:

-   Does this answer a real developer question?
-   Is the title clear?
-   Is the URL descriptive?
-   Would I bookmark this?
-   Would I share this with another engineer?
-   Does this build trust?

If not, keep refining.

> Infrastructure you can trust. Content you can trust.
